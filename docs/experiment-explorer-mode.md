# 实验：自由探索对非四人副本的服务端行为

## 1. 要回答的问题

`AllowExplorerMode = False` 的副本（讨伐战、零式、24 人大型任务），服务端是：

- **A. 暂时隐藏** —— 客户端数据把入口藏了，但设上标志位服务端就认，能进、且无怪
- **B. 根本没做这个场景** —— 服务端拒绝，或者进去了但没有"无怪"这个状态（带怪 / 区域错误）

答案决定项目走向：A 则天花板比数据高，B 则四人副本 103 张就是终点。

## 2. 为什么值得单独验

国服数据里 `AllowExplorerMode = True` 的 103 个副本**恰好等于**全部四人副本
（`ContentType = 2`），一个不多一个不少。这个"完全相等"强烈暗示自由探索是**四人副本专有设计**，
而不是人工挑出来的白名单。

但数据是**客户端侧**的。客户端表里的 False 只说明"排本器不给你这个入口"，
不等于"服务端不认"。这一层只能实测。

**先验概率偏低**，所以更要严格设计，避免把工具问题误读成服务端拒绝。

## 3. 实验工具

插件内置了一个实验窗口（`Windows/ExperimentWindow.cs`）：

- 游戏内 `/dtp` 打开主窗口 → 点「实验窗口」
- 勾选 **每帧强制 IsExplorerMode = true**

它只做一件事：每帧把 `ContentsFinder.Instance()->IsExplorerMode` 写回 `true`。
之所以要每帧写，是因为在排本器里选中副本时，客户端可能按该副本的 `AllowExplorerMode` 把它重置回去。

**排队本身刻意不代劳**，你在游戏里手动点。让排队走游戏原生的完整流程，
避免把"排队代码写错了"混进结论。

## 4. 实验设计：必须先跑对照组

这是整个实验最关键的部分。**没有对照组，负结果毫无意义**——
你无法区分"服务端拒绝"和"标志位压根没生效 / 工具坏了 / 你操作错了"。

### 对照 A：环境基线

**不勾**强制标志位，用游戏原生 UI 开自由探索进 **沙斯塔夏溶洞（rowId 4）**。

- 预期：正常进入，**没有怪物**
- 作用：确认你知道自由探索长什么样，环境正常

### 对照 B：工具基线

**勾上**强制标志位，同样进 **沙斯塔夏溶洞（rowId 4）**。

- 预期：和对照 A 表现一致，仍然无怪
- 作用：**确认工具链没有破坏原有行为**。如果这一步就异常了，停下来修工具，实验组不要做。

### 实验组

三组都用勾上标志位 + 手动排队：

| 组 | rowId | 副本 | 类型 | 等级 |
| --- | --- | --- | --- | --- |
| A | 59 | 伊弗利特歼灭战 | 讨伐战 | 50 |
| B | 103 | 巴哈姆特零式大迷宫 入侵之章1 | 零式 | 50 |
| C | 92 | 水晶塔 古代人迷宫 | 24 人 | 50 |

选 Lv50 内容是刻意的：满级角色进去有等级同步兜底，门槛最低。

**两个前置条件，不满足就没法测：**

1. **副本必须已解锁**，否则排队被拦下的原因和实验无关
2. 8 人 / 24 人内容**排不满队就进不去**。如果要快速进入，把排本器的
   **「解除人数限制」** 一起打开（`IsUnrestrictedParty`，AutoDuty 用的就是它），
   这样可以单人立即进入老副本

> 注意第 2 点会引入一个额外变量：unsync 和 explorer mode 同时开着时哪个生效本身就不确定。
> 所以如果条件允许，**先试正常排队**；只有在排不满队卡住时，再退回 unsync 方式。
> 无论用哪种，都在记录里写清楚。

## 5. 结果判读

| 观察到的现象 | 判读 |
| --- | --- |
| 申请按钮灰掉 / 提示不可用 / 排队被拒 | **B**：客户端数据层就拦住了，服务端根本收不到请求 |
| 排队成功，进本，**带怪** | **B**：标志位被忽略，服务端没有这条无怪路径 |
| 排队成功，进本，**无怪** | **A**：天花板比数据高，值得继续投入 |
| 排队成功但进的是**另一个区域**，或卡加载、黑屏 | **B**：服务端没有对应实例，行为未定义 |
| 排队后无响应 / 掉线 / 客户端崩溃 | **B**：服务端校验拦下 |
| 对照 B 也失败 | **工具或操作有问题，实验无效**，不要下任何结论 |

**特别注意"带怪"这一种。** 它容易被误读成"进得去，只是有怪"，
但它其实是**最典型的 B**：服务端认了这个副本，但完全没理会 explorer mode 这一位，
走的还是普通进本流程。对观光需求来说和拒绝没有区别。

## 6. 要记录什么

每组都记：

- rowId、用的排队方式（正常 / unsync）
- 排本器当时的样子（申请按钮是否可用）
- 是否成功进本
- **进去之后有没有怪**（这是核心观察点）
- 进去的区域对不对（地形、名称和预期一致吗）
- 任何报错文字、聊天框提示
- 截图

## 7. 结论怎么用

- **判读为 A**：`docs/design.md` §4.3 的结论要推翻，天花板重估，继续做
- **判读为 B**：四人副本 103 张就是终点。按你的计划，可以关掉这个方向，
  保留 §3 的传送能力（以太之光 + 区域内坐标传送），等官方自己扩展自由探索范围
- **实验无效**（对照 B 失败）：先修工具再重跑，不要下结论

无论哪种结果，都建议把判读结论写回 `docs/design.md`，并在仓库留一条记录。
